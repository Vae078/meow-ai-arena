# AAS 顺序占点模式 · 策划案

> 借鉴 Squad（战术小队）的 AAS（Advance and Secure）模式：据点排成一条推进链，只能按顺序占，形成战线与攻守分化。本策划案替代 `STRATEGY.md` §8 的"多据点计分"。

## 1. 一句话

N 个中立据点排成一条推进链（默认 5 个，引擎不限数量，示例图「山河关」用了 7 个），双方从各自主基地出发顺序占点；占点靠**人数优势 + 持续计时**，**首次占下新点奖励兵力(ticket)**；推到底、或耗尽敌方兵力取胜。

## 2. 地图布局

```
[南基地] ── 点1 ── 点2 ── 点3 ── 点4 ── 点5 ── [北基地]
   ↑                                                       ↑
  南家买组/出生（不是点位）                       北家买组/出生（不是点位）
```

> 上图只表示**占点顺序（链序）**，不表示点的几何位置在一条直线上——点应散布在地图上、利用地形摆出侧翼和纵深（参考 Squad 的 AAS 点位，如「山河关」的 S 形推进）。

- **全部据点初始中立**，无人占
- **主基地** = 买组/出生地（现座位的 origin + 布阵区），**不是点位、不可被占**
- 双方从基地出发向中间推进 → "抢中间 + 拉锯"

## 3. 占领规则

- **只能占与自己已占点相邻的点**（顺序推进，不能跳点、不能绕后）
- 在据点区域内，**己方活兵数 > 敌方活兵数**时，占领进度前进；劣势则后退
- 进度持续满 **10 秒** → 易主（一回合 8 秒，故跨回合才占得下）
- **无冷却/封锁**：刚被占的点可被立即反占
- "人数" = 区域内**活兵数量**（一组 12 个弓手算 12 人；投石车一组算 2 人）
- 只有"相邻已占点"是**可占点**，其余锁定 → 自然形成**战线**（前线攻、后线守）

## 4. Ticket = 兵力

- ticket = 买组的资源（取代现在的"据点每回合产增援点"）
- **开局阵容用布阵预算征召**（`seat.budget`，默认 1000，赛前写在布阵文件里）；**运行时 ticket 从 0 起步**，靠首占奖励累积
- **首次占下一个"自己从未占过的点"：一次性 +400 ticket**（之后反复易主不再给；每个点双方各能拿一次首占奖励）
- 买组花 ticket，组在基地出生、走到前线
- 不再有"据点每回合产资源"——一锤子奖励，逼你推进而非蹲守

## 5. 胜利条件

1. **占领全部据点** → 立即胜
2. **敌方兵力归 0** = ticket 花光 **且** 场上无活兵 → 立即胜
3. **时间到（保留 300 秒上限）**：比谁占点多 → 一样比剩余 ticket → 再一样平局

## 6. 战报 / LLM 视角

每回合战报新增：
- 每个点的**归属 + 占领进度**（正在被谁占、占了多少）
- 标出**可占点**（相邻已占点）和**前线点**（正在争夺的）
- 双方剩余 **ticket**

## 7. 与现状的改动

| 层 | 改动 |
|---|---|
| 地图 | 新 AAS 链式图（N 中立点 + 2 基地）；点加 `order`（链序）字段 |
| 引擎 `sim.cpp` | 占点逻辑：`scorePoints()` 改成链式顺序 + 人数优势 + 占领计时；ticket 替代 res 的"每回合产"为"首占奖励"；胜负判定改成"占满/耗尽/时间到" |
| 引擎协议 | tick 带每点归属/进度、双方 ticket |
| 桥接 | 战报显示点进度 + 可占点 + ticket |

## 8. 数值表（默认，可调）

| 项 | 值 |
|---|---|
| 据点数 | 不限（默认 5，示例图「山河关」7） |
| 布阵预算 | 1000（开局阵容）；运行时 ticket 初始 0 |
| 首占新点奖励 | +400 |
| 占领持续秒数 | 10 秒 |
| 时间上限 | 300 秒（大地图可调大，如山河关 480） |
| "人数"口径 | 活兵数 |

## 9. 待实现阶段

- S1：引擎链式占点（顺序 + 人数优势 + 计时 + 首占奖励 ticket + 胜负）
- S2：地图（链式 5 点 + 基地）+ 桥接战报
- S3：跑通 + 调数值
