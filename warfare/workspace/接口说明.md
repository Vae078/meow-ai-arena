# 接口说明

> 《纸上谈兵》引擎 `war.exe` 的命令行、指挥程序协议、批量对战格式。选手写指挥官程序（`commander.hpp`）或跑批量时看这一份。

## 1. 三个输入文件

跑一场对局需要三样东西（都在 `workspace/` 下）：

| 文件 | 内容 | 谁写 |
|---|---|---|
| 地图 `.json` | 地形、据点、座位、敌军 | 主办方（`maps/`、`levels/`） |
| 布阵 `.json` | 你开局的兵（`{"units":[{"type":"新兵","x":0,"z":0},…]}`） | 选手 |
| 指挥程序 `.cpp` / `.exe` | 每回合下令 | 选手 |

坐标约定：布阵和指挥程序都用**我方视角**——`x` 向右、`z` 朝敌人，单位米，原点在座位 `origin`，朝向 `yaw`。

## 2. war.exe 命令行

```
war run <地图.json> [--deploy 布阵.json]... [--cmd 指挥程序.exe|-]... [选项]
    跑一场。--deploy 和 --cmd 按座位顺序写（1v1 两个、混战四个、闯关一个）；--cmd - 表示这个座位不用程序。
    选项：
      --names a,b             座位名字
      --replay 回放.wrp       写回放
      --json 结果.json        结果写到文件
      --hashes 步哈希.txt     逐步哈希（验证确定性）
      --threads N             Jolt 线程数（不影响结果）
      --secs 秒               改时限（默认用地图的 time_limit）
      --rec-every K          回放每 K 步一帧（默认 2）
      --cfg 名字=值           临时改数值（可重复，例如 --cfg spear.hp=90）
      --stderr-dir 目录       每个指挥程序的 stderr 落盘
      --step-ms 20 --first-ms 2000 --wall-ms 2000 --max-timeouts 50    CPU/墙钟预算
      --match-wall-s 120      一场的墙上时钟上限（超过记 engine_timeout；0 = 不设）

war check <地图.json> <布阵.json> [--seat K]     检查布阵合不合法、算造价
war batch [--workers K] [--cfg 名字=值]... < 任务（每行一个 JSON，见 §4）
war info                                         打印全部兵种数值和规则常数（JSON）
war nav <地图.json>                               打印寻路格子（调试用）
```

更方便：`python play.py` 封装了以上命令（`play.py map` 预览地图、`play.py duel` 对战、`play.py replay` 复盘）。

## 3. 指挥程序协议（stdin/stdout）

选手只需写两个函数（见 `commander.hpp`）：

```cpp
#include "commander.hpp"
void on_start(Game& g) { ... }  // 开局一次，之后每回合
void on_tick(Game& g)  { ... }  // 每回合（8 秒 = 480 物理步）调用，在这里下令
```

程序从 stdin 读状态、向 stdout 写指令。**每回合 8 秒**，指令下完一直有效到下一回合改写。

### 3.1 init 块（开局一次，以 `END` 结束）

```
WAR 1
MODE duel                      # duel|melee|level|sandbox
MAP 山河关
SEAT 0 TEAM 0 TEAMS 2 SEATS 2  # 我方座位、队伍、总队伍数、总座位数
FRAME 0 -195 0                 # 座位 origin(x,z) 和 yaw(弧度)
LIMIT 28800 480 60             # 总步数、每回合步数(DECIDE_EVERY)、HZ
WATER static -0.6              # none | static <level> | tide <t0> <t1> <h0> <h1>
KILLY -5                       # 掉到这个高度以下出局
DEF 0 militia 10 45 9 1.2 ...  # 每个兵种一行：编号 英文名 cost hp dmg cycle windup reach speed radius climb
RULE 28 1.5 36 15 45 3.5       # 弓手射程等规则常数
GRID W H x0 z0 cell            # 半米格子高度图（供 path_dist 用）
<H 行高度，空格分隔，值=厘米或 x=空洞>
ZONES 7
Z 南前沿 circle 0 -165 12 score 0 order 0       # 区域：名字 circle/rect 参数 score 值 order 链序
SCORE -                        # 计分区名字，- = 无
UNITS 1
0 0 0 0 新兵                   # 单位编号 兵种 队伍 座位 标签
PROPS 0
END
```

### 3.2 tick 块（每回合，以 `E` 结束）

```
T <tick> <step> <water_cm> <score…每队> <res…每队>   # tick=回合号；res=每队 ticket（AAS 买组用）
U <n>
<id> <state> <x_cm> <y_cm> <z_cm> <vx_cm> <vz_cm> <hp*10> <cd> <flags> <facing*1000> <order> <target>
G <n>                          # 迷雾幽灵：不可见但目击过的敌方单位
<id> <x_cm> <z_cm> <step>
C <n>                          # AAS 顺序占点：每点（按 order 排序）
<owner> <timer>                # owner=-1 中立 / 0 或 1 归属；timer=占领进度步(>0 正在被占)
V <n>                          # 本回合事件（terrain_removed / destroyed / released / boss …）
B <n>                          # 镇山兽
P <n>                          # 道具
S <n>                          # 飞行中的石头/雪球
E
```

所有坐标都是**世界坐标厘米**；`commander.hpp` 会自动转成本地坐标米（`g.units[].x/z`）。迷雾：敌方单位只在己方任一单位视野内可见（`g.units` 里没有的就是看不见的，去 `g.ghosts` 找最后目击）。

### 3.3 指令（stdout，每回合一行）

回复第一项必须是回合号，之后空格分隔若干指令。`commander.hpp` 提供了封装：

| 封装 | 输出 | 含义 |
|---|---|---|
| `move(id,x,z)` | `M id x_cm z_cm` | 走到 (x,z)，自动绕路；到了原地守 |
| `move_straight(id,x,z)` | `L id x_cm z_cm` | 同上但不绕路（自己负责别掉下去） |
| `attack(id,target)` | `A id target` | 追打目标（单位/道具），目标没了回自由 |
| `hold(id)` | `H id` | 原地守（长枪兵架枪） |
| `free(id)` | `F id` | 自由行动（默认行为） |
| `aim(id,x,z)` | `P id x_cm z_cm` | 弓手/投石车朝地点盲射 |
| `detonate(id)` | `D id` | 炮仗兵立刻点火 |
| `push(id,snowball)` | `U id snowball_id` | 推雪球（大锤：敲一下） |
| `buy(kind)` | `B kind` | AAS：花 ticket 在基地买一整组（boss/lord 不可买，会静默忽略） |

## 4. batch 批量对战

`war batch` 从 stdin 读任务，每行一个 JSON 对象，每行一个结果 JSON 到 stdout：

```json
{"id":1, "map":"maps/山河关.json", "deploys":["a/d0.json","a/d1.json"], "cmds":["bots/x.exe","bots/y.exe"], "names":["甲","乙"], "replay":"r/1.wrp", "secs":480, "rec_every":2}
```

| 字段 | 说明 |
|---|---|
| `id` | 结果里原样带回（默认行号） |
| `map` | 地图路径（必需） |
| `deploys` / `cmds` / `names` | 每座位一份；`"-"` = 不用（布阵空 / 不用程序） |
| `replay` / `hashes` | 回放 / 逐步哈希输出路径（可省） |
| `secs` | 改时限（-1 = 用地图的） |
| `rec_every` | 回放每 K 步一帧 |

## 5. 结果 JSON

`run` / `batch` 的结果是一个 JSON 对象，关键字段：`winner`（胜方座位，-1 平）、`reason`（胜负原因）、`mode`、`score`、每座位 `deploy_ok`/`deploy_cost`/`faults`（指挥程序故障）。具体以 `python play.py` 的展示和 `summary.py` 为准。

## 6. 规则要点（写程序前必读）

- 程序必须**确定**：不许读时钟、不许用随机数（裁判和本地用同一模拟器，结果要一致）。
- 调试输出写 stderr（`g.log(...)` 或 `std::cerr`），别写 stdout。
- 每回合 8 秒（480 步），指令下完一直有效；同一回合内引擎继续推演物理，下回合才能再改。
- AAS 顺序占点：只能占与自己已占点相邻的点（`g.caps` 按链序排列，`g.zones[].order` 给序号），首占新点 +400 ticket，买组花 ticket。
