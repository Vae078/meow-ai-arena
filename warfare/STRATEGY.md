# warfare：全面战争式的组队对战，给 LLM 实时指挥（设计稿）

> 状态：设计稿（未实施）。独立于 `battle/` 的新游戏目录；引擎等基础设施直接复用 `battle/` 的（复制粘贴即可），本文只定义"新游戏长什么样"。
>
> 背景：`battle/`（《纸上谈兵》）是"赛前写 commander.cpp → 离线跑完"的赛道；`battle/live/` 是"LLM 实时指挥"的桥接实验。本目录 `warfare/` 是**专门为 LLM 实时指挥而设计的新游戏**——目标是让两个 LLM 打一场**有深度、有博弈**的对决。

## 1. 一句话方案

把战争抽象成**"组"（squad，全面战争式的方阵单位）**：双方 LLM 每回合花资源**按组购买兵力**、给各组下**意图**（去占哪个点、打哪个组、守哪里），引擎在回合内**实时演算**组的编队战斗。核心机制：**同时回合（WEGO）+ 战争迷雾 + 多据点计分 + 按组购买 + 组级相克**——让**决策质量盖过决策带宽**。

## 2. 背景与动机

这次只看 **LLM vs LLM**，不引入确定性程序（确定性程序在"两 LLM 博弈"里没有意义，也没有优势——它可预测、可读穿，反而吃亏）。

那问题就变成：**什么样的游戏，能让两个 LLM 的对决好看、有深度，而不是退化？**

全信息 + 顺序行动（象棋式）会让两 LLM 退化成"谁开局算得死"；连续实时 + 逐兵微操会让 LLM 暴露带宽短板。所以：

- **不完全信息 + 同时行动**（扑克式）→ 有读心、试探、虚张声势、混合策略；
- **组为唯一单位** → 决策粒度天然粗、天然高，LLM 不用逐兵微操；
- **多据点 + 经济** → 有取舍、有承诺、有滚雪球。

## 3. 核心单位：组（squad）

> 这是整个游戏的地基，必须先定死。

**一个"组" = 同兵种的一队士兵，编成一个方阵，作为一个整体行动和战斗**（全面战争里的一个 unit）。它同时是：

- **经济单位**：花钱买的是"一组步兵"（20 人），不是 20 个兵；
- **指挥单位**：LLM 只对"组"下令，永远不对组内单个兵下令。

**组的参数**：

| 字段 | 说明 |
|---|---|
| 兵种 | 决定方阵类型、克制关系 |
| 人数 n | 初始满编（如步兵组 20、弓手组 15、骑兵组 12、投石车组 4） |
| 剩余人数 | 组内士兵阵亡会减员，减员→输出/血量下降 |
| 造价 | = 满编人数 × 单体造价（沿用 battle 的 `KindInfo.cost`） |
| 编队 | 方阵/线阵/楔形等，影响接战效率（组内自动，LLM 不管） |

**规模**：一场双方各约 **6～10 个组**。LLM 每回合指挥的是这 6～10 个组，不是几百个兵——**带宽问题在接口层就消失了**。

## 4. 三条设计原则

1. **决策质量 > 决策带宽**：任何机制都要问"它奖励想得对还是动得快"，奖励后者的砍掉。
2. **局内公平**：两 LLM 规则完全对称（同一回合时长、同一迷雾、同一资源公式）。
3. **抽象掉微操**：LLM 下意图，组的编队战斗全自动；LLM 永不逐兵/逐帧微操。

## 5. 博弈论定位：象棋 → 扑克

- **同时行动**：没有唯一最优解，最优策略是**混合策略**（随机化、虚张声势）。
- **不完全信息**：核心技能是**信念形成 + 对手建模**（对方在干嘛、他以为我在干嘛）。

关键反转：**LLM 的 `temperature` 采样 = 混合策略生成器**（是特性，不是 bug）；反过来，"可预测"的一方会被读穿。

## 6. 回合结构：WEGO（同时回合）

1. 时间切成固定长度的**指挥回合**（默认 **8 秒**，可配，待实测）。
2. **回合边界 = 决策点**：引擎把上一回合末的、**迷雾过滤后**的状态发给两 LLM，两边**同时**提交命令（同步阻塞，引擎等两边都回）。
3. **回合内实时演算**：引擎以 60Hz 推演，各组执行「上回合命令 + 编队自主 AI」。
4. 整局上限默认 **5 分钟**（≈ 37 回合）。

公平保证：两边同一回合时长、同一回合边界、同时决策；回合内物理确定性，唯一随机源 = 双方 LLM 采样。

## 7. 战争迷雾与情报战

- 每组有**视野半径**（骑兵 > 弓手 > 近战）；敌方组只在「己方任一组视野内」可见（位置、朝向、兵种、剩余人数）。
- 视野外的敌方组不可见，但保留**「最后目击」幽灵**（位置 + 时间 + 朝向）。
- **敌方构成开局隐藏**，靠侦查揭示。
- **据点归属永远可见**（公开的战略信息，制造"我知道你知道我知道"）。
- 回放记全量状态（观战/复盘），迷雾只作用于**实时输入视图**。

为什么：迷雾让"对看不见的部分形成信念"成为核心技能，同时催生"花多少资源去探 vs 去打"的战略权衡。

## 8. 多据点与计分胜利

- 地图放 **3～5 个据点**；据点区域内「你方组造价 > 对方组造价」持续倒计时归零则易主。
- 每回合结束，每个据点给归属方固定分（默认 +10/回合）。
- 胜负：整局**总分高者胜**；全歼对方 / 摧毁对方主帅 → 立即胜；总分相同 → 比剩余造价 → 比据点数。

为什么：把"一波定胜负"拉成"多线、多回合的持续博弈"，制造不可同时最优的取舍（守旗 vs 压人、抢东点 vs 西点、分兵 vs 集中）。

## 9. 按组购买经济（承诺与滚雪球）

- 每回合结束，每个己方据点产**增援点**（默认 +40/据点/回合）。
- 增援点花在**己方基地**买组（`buy 兵种`），组在基地满编出生、编队走到前线（时间成本 = 承诺）。
- 可选：增援点也可**升级**现有组（补员到满编 / +攻 +防），制造"扩军 vs 精锐"的第二层取舍。

为什么：组比兵更"重"，买一组是更强的承诺；从基地走到前线的时间是长因果链；资源随据点滚雪球——这些都是 RTS build-order 宏观，也是 LLM 规划能力的落点。

## 10. 兵种与组级相克

沿用 battle 的 11 兵种 + 道具，相克关系在**组级**成立，做成非传递环：

| 维度 | 关系 | 示例 |
|---|---|---|
| 兵种环 | 枪克骑、骑克弓、弓克枪（非传递） | 枪兵组架枪、骑兵组冲锋、弓手组远程 |
| 定位环 | 近战 < 远程 < 攻城 < 掩体 | 弓手组怕被绕后、投石车组怕被近身 |
| 体型/造价 | 人海 > 高造价单体（拉扯）> 人海 | 大块头/镇山兽组克制密集，但被风筝 |

关键：相克表只有**在迷雾下**（构成隐藏）才变成博弈；全信息时大家直接抄最优解。

## 11. LLM 每回合决策界面

### 输入：观察摘要（迷雾过滤后）

```
【第 12 回合 · 96.0 秒 · 上限 300 秒 · 得分 我 320 : 敌 240】
据点：东山(我) 桥头(敌) 中营(争夺中) 北坡(中立)
我方 8 组（总造价 720）：
  #1 步兵组 (4.2,-8.1) 满编20
  #2 枪兵组 (5.3,-12.0) 18/20 架枪
敌方可见 5 组（另有 2 组最后目击）：
  #9 骑兵组 (4.0,15.0) 满编12 冲锋
  [幽灵] #11 弓手组 最后目击 (8.0,10.0) 3.2 秒前 朝北
增援点：我 240（+40/回合）  敌 未知
上一回合：#2 减员 2；我丢了「中营」
```

### 输出：意图（组级 + 经济）

| 动词 | 含义 |
|---|---|
| `move 组 目标点` | 整组移动（保持编队） |
| `attack 组 目标组` | 整组攻击 |
| `hold 组` / `free 组` | 驻守 / 回默认 |
| `scout 组 方向` | 派侦查 |
| `buy 兵种 [×n]` | 花增援点买组 |
| `upgrade 组` | 补员/升级 |

要点：LLM 只对**组**下令，组内编队战斗全自动；坐标是本地坐标；`buy/upgrade` 是经济动作，`move/attack/...` 是指挥动作。

## 12. 引擎复用与新增

> 新游戏不在 `battle/` 下实现，但基础设施直接复制 `battle/` 复用。

| 复用（复制粘贴即可） | 新增/改动 |
|---|---|
| 物理（Jolt）、单位战斗/寻路/索敌 AI（`sim.cpp`） | **组（squad）层**：组 = 一组同兵种士兵 + 编队 AI + 组级指令扇出 |
| 指挥程序子进程边界与 stdin/stdout 协议（`commander.hpp`） | 回合化 tick、迷雾过滤、组/据点/资源字段 |
| 回放机制与格式框架（`回放格式.md`，只追加字段） | 按组购买、据点占领/计分、增援 |
| 兵种数值 `KindInfo`、道具、地图 JSON 地形图元 | 迷雾视野计算、编队 |
| LLM 桥接（`battle/live/` 的 protocol/summary/commands/providers/memory） | 摘要/指令改为"组"粒度 |

**组层的实现建议**：在现有"每兵一个单位"的模拟之上加一层**组控制器**——收到组级指令后，按编队偏移扇出成组内各兵的目标点/目标（最小改动、最大化复用）。先不做"整组一个碰撞体"的大改。

## 13. 公平性

两 LLM 规则完全对称：同一回合时长、同一迷雾规则、同一资源公式、同一可见性判定。唯一随机源 = 双方各自 LLM 的采样（混合策略，是特性）。局外因素（墙钟、API 延迟、模型强弱）不进评分——正式对比建议同模型/同配置。

## 14. 关键权衡

| 决策 | 选择 | 代价 | 为什么不选另一个 |
|---|---|---|---|
| 单位粒度 | 组（squad） | 失去单兵微操 | 逐兵下令 token 爆炸、LLM 带宽不够 |
| 回合制 vs 连续实时 | WEGO | 观感从 RTS 变"同时回合战术" | 连续实时是带宽碾压根源 |
| 迷雾 vs 全信息 | 全迷雾 | 引擎要加视野计算 | 全信息下两 LLM 退化成算死局 |
| 按组经济 | 有 | 引擎改动较大 | 无经济就无 build-order 和承诺 |
| 回放 | 全量记录、迷雾只作用于实时输入 | 回放文件略大 | 观战/复盘需要全信息 |

## 15. 分阶段落地

- **S1：组层 + WEGO 回合化**（地基）。验证：mock AI 全链路跑通，两边公平。
- **S2：战争迷雾 + 最后目击**。验证：LLM vs LLM 是否出现侦查/读心行为（而不是无脑平推）。
- **S3：多据点 + 计分胜利**。验证：是否出现"取舍式"决策、多线博弈。
- **S4：按组购买经济 + 组级相克调参**。验证：是否出现 build-order 深度和滚雪球。

**可证伪判据**：S2 做完后，若 LLM vs LLM 的对局仍退化成"各自平推、无侦查无博弈"，说明迷雾/摘要没把"信息差"传达到位，回头打磨 §11 的决策界面。

## 16. 范围外与未来扩展

本期不做：完全异步决策、图像输入、局内改布阵（召唤≠改开场构成）、真正的 RL 训练（改权重）。

未来扩展：科技树（在 §9 上再加长承诺链）、非对称地图、实时迷雾观战、组内兵种混编。

## 17. 待确认问题

1. 回合时长（默认 8s，待实测）。
2. 据点数量、计分速率、增援点速率（需平衡测试）。
3. 迷雾是否考虑地形遮挡（建议先只按距离半径，遮挡留扩展）。
4. 各组满编人数（步兵 20/弓手 15/骑兵 12/投石车 4 是建议值）。
5. 是否允许买主帅/镇山兽组（建议禁止，超兵只走开场）。
6. 组内是否可混编兵种（建议先纯兵种组，混编留扩展）。
