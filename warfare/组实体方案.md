# 组实体方案：组（Squad）作为引擎一等实体

> 把「组」从 LLM 层的松散抽象（兵种名 → 我所有该兵种的兵），下沉成**引擎的真实实体**——组有独立身份（「第 1 组长枪兵」≠「第 2 组长枪兵」）、有持久状态，LLM 和桥接都以组为单位通信，组内编队/协同由引擎自动完成。

## 1. 背景与问题

现在链路里的「组」是假的：

```
LLM 层：组（兵种名 move militia = 我所有 militia）
   ↓ 桥接层扇出（squads.py：resolve_mine 按兵种聚合 → spread 编队偏移 → 逐兵 token）
引擎层：兵（每个兵一个独立 Jolt 刚体，组在生成后就消失了）
```

导致：
- 引擎不知道组，无法按组协调（组被打散就散架）；
- 买两个长枪兵组，引擎分不清「第 1 组」和「第 2 组」，LLM 也无法分别指挥；
- 桥接层做「兵种名 → 所有兵」的扇出，语义就是错的（不能只指挥其中一组）。

## 2. 目标

1. **数值层以组展开**：经济/战报/指挥的最小单位是「组」（一组多少钱、组内几个人）。
2. **引擎按组操作**：组是持久实体，组内兵由引擎的组控制器协调（编队/索敌/驻守）。

## 3. 数据模型

引擎内部新增 `Squad` 结构，`Unit` 加 `squad` 关联：

```cpp
struct Squad {
    int id = -1;               // 组 id（全局唯一，买组时分配）
    int seat = -1, kind = 0;   // 座位、兵种
    std::vector<int> members;  // 组内兵的 unit id
    int formation = 0;         // 阵型：0 方阵（先只做方阵）
    // 组级意图（由组控制器扇出成组内兵指令）
    Order ord;                 // 复用 Order：O_MOVE/O_ATTACK/O_HOLD/O_FREE
    int targetSquad = -1;      // 攻击的目标组 id
};

struct Unit {
    ...
    int squad = -1;            // 所属组 id（-1 = 无组：主帅/守军单兵）
};
```

## 4. 数值层（SquadDef）

把现有 `squad_size()` 扩展成完整的 `SquadDef`：

```cpp
struct SquadDef {
    int size;        // 组内人数：新兵12 盾卫8 长枪兵8 弓手12 骑兵6 大锤6 炮仗兵6 投石车2 大块头1
    float cost;      // 组价 = size × 单兵 cost：新兵组120 弓手组360 骑兵组480 …
    int formation;   // 默认阵型（0 方阵）
};
```

- **经济单位** = 组：`buy 长枪兵` 花 200 买一整组，没有「买单个兵」。
- **战报/协议单位** = 组：LLM 看到「第 3 组长枪兵 8 人 中心(…)」。
- **指挥单位** = 组：指令对 `squad_id` 下。

## 5. 组级指令协议（桥接 → 引擎以组为单位）

新增组级 token（`G` 前缀，与逐兵 token 区分），`applyOrders` 增加解析分支：

| token | 含义 |
|---|---|
| `GM squad_id x z` | 组移动到 (x,z)，组内自动编队 |
| `GA squad_id target_squad` | 组攻击目标组，组内自动就近分配目标 |
| `GH squad_id` | 组驻守，组内展开阵型（长枪兵自动架枪） |
| `GF squad_id` | 组自由行动 |
| `GB kind` | 买组（沿用现有 `B`，语义明确为组） |

**桥接层不再扇出**：删掉 `squads.py` 的「兵种名 → 所有兵 → 逐兵 M」，LLM 直接下 `GM 3 -110 92`，引擎内部由组控制器扇出。

**逐兵指令保留作兜底**：现有 `M/A/H/F/P/D/U`（id = 兵 id）继续可用，LLM 想微操单兵时用。

## 6. 组内协调 AI（引擎内组控制器）

每个物理步，组控制器把「组级意图」扇出成「组内兵指令」：

1. **组移动**：组中心 + 阵型偏移 → 组内每个兵的目标点（现有 `spread()` 搬进引擎，逐帧维持队形）；
2. **组攻击**：组内兵就近分配目标（现有 `assign_targets` 搬进引擎，按组统一索敌/集火）；
3. **组驻守**：组内兵展开阵型、长枪兵自动架枪、弓手自动找射击位；
4. **减员**：组内兵阵亡 → `members` 收缩 → 阵型自动收紧，组不因死几个人就散架。

**组内兵仍是独立 Jolt 刚体**（复用现有物理/战斗/寻路），组控制器只做上层协调，不做「整组一个碰撞体」。

## 7. 协议状态（引擎 → 桥接 → LLM 以组为单位）

- **init**：加 `SQUADS` 块，列出每组的 `id/kind/seat/members`。
- **tick**：加 `Q` 块（组状态），LLM 只看组、不看兵（迷雾同样按组过滤）：

```
Q 5                          ← 5 个组
3 spear 8 0 -11000 9200 1     ← 组id 兵种 人数 中心x(cm) 中心z(cm) 状态(0自由 1驻守 2攻击 3行军)
```

`U`（逐兵）保留给回放/精细操作，LLM 战报走 `Q`。

## 8. 分阶段落地

| 阶段 | 内容 | 改动 |
|---|---|---|
| S1 | 引擎加 `Squad` 实体 + `Unit.squad`，`spawnSquad` 建组、`buy` 按组 | `defs.hpp` + `sim.cpp` 数据结构 |
| S2 | 组级指令 `GM/GA/GH/GF` + 组控制器扇出（移动/攻击/驻守） | `sim.cpp` 指令 + 组协调 |
| S3 | 协议发组信息（init `SQUADS` + tick `Q`） | `sim.cpp` 协议 + `commander.hpp`/`protocol.py` |
| S4 | 桥接层改组粒度（去扇出，LLM 对 `squad_id` 下令），战报按组 | `live/squads.py`/`summary.py`/`commands.py` |
| S5 | 数值调平 + 组内协同打磨 | 平衡测试 |

## 9. 已拍板的决策

| 决策 | 选择 |
|---|---|
| 组内兵是否独立刚体 | 是（组控制器协调，兵独立物理；不做整组碰撞体） |
| 逐兵指令 | 保留作兜底（`M id` 等仍可用） |
| 阵型 | 先只做方阵，线阵/楔形留扩展 |
| 组补员/合并 | 先不做，组减员就减员，留扩展 |
